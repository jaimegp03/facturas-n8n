## Reglas de calidad (obligatorias)
- **Nunca inventes parámetros de nodos.** Antes de usar un nodo consulta su esquema y versión reales en la instancia (`get_node_types` / `search_nodes`) y valida cada nodo y cada workflow (`validate_node_config`, `validate_workflow`) antes de desplegar.
- Workflows con prefijo `FACT —`. Tras cada cambio, exporta el JSON a `n8n/workflows/<slug>.json` (sin credenciales en claro).
- Todas las cifras se calculan en Code nodes. El LLM solo extrae (con `responseSchema`) o redacta; nunca suma ni inventa números. Un Code node comprueba que el texto del asesor solo contiene cifras que estaban en sus datos.
- Webhooks: Header Auth (`X-API-Key`, credencial de n8n "FACT API Key", id `factApiKey0000001`) y CORS que acepte `null` (file://) y localhost. `allowedOrigins` de n8n es una lista exacta separada por comas (sin comodines de puerto): usa la misma lista en todos los webhooks (ver CLAUDE.md).
- Rutas con parámetro (`/facturas/:id`): el Webhook lleva `webhookId: "facturas"` y `path: ":id"` (n8n antepone el webhookId en rutas dinámicas). n8n 2.42 solo anuncia **un** método en el preflight CORS de una ruta dinámica, por eso PATCH/DELETE existen también en la ruta estática `/facturas?id=N`, que es la que debe usar la web.
- Recurrentes (POR_ANIO, centimos, claveProveedor, ordenFecha, calcularRecurrentes) están duplicados a propósito entre las marcas `// === COMÚN Recurrentes` en API «Resumen: calcular», Asesor «Analizar y proponer» y Exportar Excel «Generar Excel»: mantén los tres bloques idénticos (coste_anual = importe × periodos/año; coste_mensual = anual/12 redondeado al céntimo).
- **Code nodes y ExcelJS (task runner)**: el código corre en un contexto vm distinto, así que `instanceof Date`/`Array` de ExcelJS fallan con objetos creados en el Code: un `Date` se escribe como texto JSON y `addRow([...])` / `row.values = [...]` dejan las celdas vacías. Escribe fechas como número de serie de Excel (`ms/86400000 + 25569`) con `numFmt 'dd/mm/yyyy'` y las filas celda a celda (`getCell().value`). `addTable({rows})` sí funciona.
- Para no pegar código largo en las llamadas, el MCP integrado también se puede llamar desde Python por HTTP (`http://localhost:5678/mcp-server/http`, cabecera `Authorization: Bearer $N8N_MCP_TOKEN`, JSON-RPC `initialize` + `tools/call`, forzar UTF-8 al leer la respuesta); así se generan el código SDK o los `setNodeParameter /jsCode` desde archivos locales.
- Prueba los Code nodes fuera de n8n ejecutándolos dentro del contenedor con `node` en un `vm.createContext` (reproduce el problema de realms), con luxon de `/usr/local/lib/node_modules/n8n/node_modules/luxon` y ExcelJS de `/usr/local/lib/node_modules/exceljs`.

Mantén las cuatro copias idénticas (edítalo en un archivo local y pégalo en todas con `setNodeParameter /jsCode`) y compruébalo con `tests/probar_gestoria_a.py --bloques` tras exportar.
- Modo gestoría: `docs/diseno-gestoria.md` es el contrato (tandas A, B y C hechas). Si algo no se puede hacer así en n8n 2.42, dilo y propone alternativa.
- El bloque `// === COMÚN Fiscal` (fxPreparar a EUR con tipo_cambio, fxFilasLibro, fxCalcularFiscal 303/111/115/349/347, fxAsientos, CSV) está en **dos** sitios: FACT — Fiscal «Fiscal: calcular» y Exportar Excel «Generar Excel». - En Git Bash los heredocs largos con `$('…')` a veces fallan («unexpected EOF»): escribe los scripts con la herramienta Write y ejecútalos.

- `fact_reglas`: proveedor_norm, categoria, subcategoria, usos, cliente_id (null = global; la del cliente prevalece), cuenta_gasto.
- `fact_categorias`: nombre, orden, activa, cuenta_pgc — la taxonomía editable en un único sitio (28 activas desde 2026-10-16: Agua, Luz, Gas y Telefonía e internet reemplazan a «Suministros (…)», desactivada pero no borrada; + 8 de empresa; «Otros» orden 99; workflow TEMP `1I09fe1HC2Au62mz` a archivar).
- `fact_clientes`: nombre, nif (normalizado, sin «ES»), regimen_iva (general|recargo_equivalencia|simplificado|particular), prorrata_pct, activo, creado. Fila 1 = «Personal» (particular), a la que pasaron las 15 facturas reales.
- `fact_errores`: fecha, workflow, nodo, mensaje, ejecucion_id.
- `fact_recomendaciones`: fecha, desde, hasta, json, cliente_id (GET /recomendaciones?cliente_id = la última de ese cliente).
- `fact_movimientos`: cliente_id, cuenta, fecha, fecha_valor, concepto, importe (− cargos), referencia, factura_id, estado (pendiente|conciliado|ignorado), origen (n43|csv), hash, creado.
- Importes de cada factura en su moneda (también cuota_autorrepercutida y cuota_deducible); /fiscal, libro, asientos y Excel los convierten a EUR con tipo_cambio.
- Tipos: importes, iva_tipo, confianza, orden y usos son `number`; `activa` es `boolean`; **todas las fechas son `string`** (fecha_emision/vencimiento `AAAA-MM-DD`; creado/actualizado/fecha ISO con zona Europe/Madrid) para evitar desplazamientos de zona horaria del tipo `date` y poder comparar/filtrar lexicográficamente. `lineas_json` es JSON en texto; `errores_validacion` es texto con los motivos separados por ` | ` (null si no hay).
