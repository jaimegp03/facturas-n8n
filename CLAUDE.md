# Facturas n8n

Sistema de gestión de facturas: una web (`web/index.html`) sube facturas a n8n, que las extrae con Gemini, las clasifica, detecta duplicados y suscripciones, resume el gasto, recomienda ahorros y exporta un Excel con estilos.

**Guía de usuario:** `docs/GUIA.md` (punto de entrada del README). Hay que mantenerla al día cuando cambie la web (botones, secciones, atajos, avisos) o el flujo de uso.

Para cualquier trabajo sobre este sistema usa el subagente `facturas-n8n` (`.claude/agents/facturas-n8n.md`). Mantén este archivo y el subagente al día cuando cambie algo.

### FACT — Ingesta: decisiones
- Respuesta: `{resultados:[{archivo, estado, factura?, error?, extraccion?}]}`. Estados: `ok`, `revisar`, `posible_duplicada` (se guardan), `duplicada` (no se guarda; `factura` = la existente), `rechazado` (tipo/tamaño), `error` (fallo de Gemini; no se guarda, se puede reintentar). `extraccion = {modo: texto|vision, modelo}`. HTTP 200 salvo petición sin archivos (400).
- El tipo se valida por firma de bytes (no por extensión ni por el MIME del cliente). Límite 10 MB por archivo.
- Procesa los archivos de una petición **en secuencia** (Split in Batches de 1), así un duplicado dentro de la misma petición se detecta. El orden interno sigue el orden en que n8n recibe los binarios, no necesariamente el de envío; la respuesta se ordena igual.
- Texto: PDF con ≥ 60 caracteres alfanuméricos extraídos → se envía el texto; si no (imagen, PDF escaneado) → Gemini visión con el binario. Extracción de texto y estructurada van en **una sola llamada** a Gemini (`responseMimeType: application/json` + `responseSchema`, categoría como `enum` leído de fact_categorias).
- El nodo nativo Google Gemini (v1.2) no admite `responseSchema`, por eso se usa HTTP Request a `generativelanguage.googleapis.com` con `predefinedCredentialType` `googlePalmApi`.
- **La regla aprendida se aplica tras la extracción**, porque el proveedor solo se conoce entonces: se normaliza (`proveedor_norm`: minúsculas, sin acentos ni puntuación, sin sufijos societarios finales como S.A., S.L.U., B.V., Ltd.) y si hay fila en fact_reglas con ese `proveedor_norm`, su categoría prevalece (`origen_categoria = "regla"`); si no, `"llm"`.
- Validación en Code (céntimos enteros): |base + iva_cuota − total| ≤ 0,02; total > 0; fecha de emisión válida y no futura (Europe/Madrid); confianza ≥ 0,75; proveedor presente. Cualquier fallo ⇒ `revisar` con `errores_validacion` (motivos separados por ` | `).
- Duplicado exacto: SHA-256 ya presente en fact_facturas con estado ≠ borrada. Duplicado lógico: mismo `proveedor_norm` + `numero` + `total` (al céntimo) ⇒ `posible_duplicada` (sí se guarda).
- Original en `/home/node/.n8n-files/facturas/AAAA/MM/<sha256>.<ext>` con AAAA/MM de la **fecha de emisión** (si no es válida o es futura, mes de subida). El nodo Read/Write Files de n8n 2.42 no crea carpetas, así que el Code **"Crear carpeta"** (entre "Decidir estado final" y "Guardar original") comprueba que la ruta está dentro del almacén y tiene la forma `AAAA/MM/<sha256>.<ext>` y hace `fs.mkdirSync(dir, {recursive:true})`. Ya no hay carpetas pre-creadas ni límite de años.

### FACT — API: decisiones
- Un workflow, 8 Webhook triggers (GET /facturas, GET /resumen, GET /categorias, GET /archivo, PATCH y DELETE /facturas/:id, PATCH y DELETE /facturas?id=N), todos con Header Auth "FACT API Key" y la lista CORS de arriba. Todas las respuestas JSON acaban en un único «Responder» que devuelve `$json.body` con código `$json.status`; la única excepción es el binario de GET /archivo, que tiene su propio «Responder archivo». errorWorkflow = FACT — Errores.
- GET /archivo?id=N (ruta estática, no `/archivo/:id`, por la limitación CORS de las rutas dinámicas): valida id → lee la fila de fact_facturas (404 si no existe o `estado = borrada`) → exige que `archivo_ruta` empiece por `/home/node/.n8n-files/facturas/`, sin `..` y solo con `[A-Za-z0-9._/-]` (400; esto también impide que la ruta se interprete como patrón glob en Read/Write Files) → «Archivo: leer disco» (Read/Write Files, `alwaysOutputData` + `continueRegularOutput`) → si no hay binario, 404 JSON. `mime` que no parezca un tipo MIME ⇒ `application/octet-stream`. Desde la web, como exige `X-API-Key`, no vale un `<img src>`: hay que hacer `fetch` con la cabecera y usar `URL.createObjectURL(blob)`.
- **Rutas con `:id`**: en n8n las rutas dinámicas llevan delante el `webhookId` del nodo; por eso los Webhooks de PATCH/DELETE tienen `webhookId = "facturas"` y `path = ":id"`, y la URL queda `/webhook/facturas/:id`. Si se duplica el workflow o se recrean esos nodos, n8n les pone un UUID nuevo y la URL cambia: vuelve a fijarlo.
- **Limitación de n8n 2.42 (CORS)**: en el preflight de una ruta dinámica n8n anuncia un solo método (`Access-Control-Allow-Methods: OPTIONS, DELETE`), así que un navegador no puede hacer PATCH a `/facturas/:id`. Por eso existen también `PATCH /facturas?id=N` y `DELETE /facturas?id=N` en la ruta estática (su preflight anuncia `DELETE, GET, PATCH, POST`). **La web debe usar la variante `?id=N`**; scripts y curl pueden usar cualquiera de las dos.
- GET /facturas: la Data Table no tiene offset, así que se leen las filas de `usuario_id = default` y se filtra, ordena y pagina en Code. `desde/hasta` sobre `fecha_emision` (incluidos), `categoria` exacta, `proveedor` subcadena sin distinguir mayúsculas (semántica ilike), `tipo` = `tipo_gasto`, `estado` exacto; sin `estado` se excluyen las `borrada`. Orden `fecha_emision` desc (sin fecha al final) y `id` desc. `pagina` ≥ 1, `por_pagina` 1..200 (def. 50); fuera de rango ⇒ 400. Una página posterior a la última devuelve `items: []`.
- GET /resumen (todo en Code, céntimos enteros): si faltan `desde/hasta`, últimos 12 meses hasta hoy (Europe/Madrid): `hasta = hoy`, `desde = hoy − 1 año + 1 día`. Cuentan `ok`, `revisar` y `posible_duplicada`; se excluyen `borrada` y `duplicada`. Respuesta `{desde, hasta, total, num_facturas, por_estado, sin_fecha, por_categoria:[{categoria,total,num,pct}], por_mes:[{mes,total}], top_proveedores:[{proveedor,total,num}], recurrente:{mensual, anual, detalle:[{proveedor,categoria,tipo_gasto,periodicidad,ultimo_importe,coste_mensual,coste_anual,ultima_fecha}]}, comparacion_periodo_anterior:{desde,hasta,total,diferencia,pct}}`.
  - `por_estado` cuenta todas las filas del periodo (también borrada/duplicada, que no suman). `por_mes` incluye todos los meses del periodo, también a 0. `pct` con 2 decimales (puede sumar 99,99 por redondeo). `top_proveedores` agrupa por `proveedor_norm` y muestra el nombre de la factura más reciente.
  - Recurrente: facturas `suscripcion`/`contrato` del periodo; por cada `proveedor_norm` se toma la **última** (fecha_emision). `coste_anual = importe × periodos/año` (semanal 52, mensual 12, bimestral 6, trimestral 4, semestral 2, anual 1) y `coste_mensual = coste_anual / 12` redondeado al céntimo; `recurrente.anual` y `.mensual` son la suma de esos valores (no mensual × 12). Sin periodicidad ⇒ aparece en el detalle con costes null y no suma.
  - Periodo anterior: misma duración en días, inmediatamente antes; `pct` null si el anterior es 0.
- PATCH (`metodo_pago` se normaliza con `normalizarMetodoPago`, primera letra en mayúscula): lista blanca `proveedor, nif, numero, fecha_emision, fecha_vencimiento, base, iva_tipo, iva_cuota, total, moneda, metodo_pago, categoria, subcategoria, tipo_gasto, periodicidad, estado` (estado ≠ borrada). Tipos: textos o null (proveedor no vacío), importes numéricos (número o cadena con punto), fechas `AAAA-MM-DD` válidas (fecha_emision no nula), `moneda` ISO de 3 letras, `categoria` activa en fact_categorias, enums de `tipo_gasto`/`periodicidad`/`estado`. Si `tipo_gasto` final es `puntual`, `periodicidad = null`. Revalida con `validarFactura` (bloque COMÚN; sin umbral de confianza: la corrección manual sustituye a la lectura): si falla ⇒ `revisar` con `errores_validacion` (aunque el cliente pida otro estado); si pasa ⇒ el estado que pida el cliente, o `ok` si estaba en `revisar`, o el que tenía (en `posible_duplicada` se conserva su aviso). Recalcula `proveedor_norm` si cambia el proveedor; `actualizado = ahora`. Si cambia la categoría ⇒ `origen_categoria = "manual"` y upsert en fact_reglas (`proveedor_norm` → categoría, subcategoría, `usos + 1`); cambiar solo la subcategoría también marca `manual` pero no toca reglas.
- DELETE: `estado = borrada`, `actualizado = ahora`. 404 si no existe; repetirlo sobre una ya borrada devuelve 200 con `ya_borrada: true`. Un PATCH con otro estado la "desborra".

### FACT — Asesor de gastos: decisiones
- Disparadores: Webhook POST /asesor y Schedule «Cada mes (día 1, 08:00)» (Europe/Madrid) **desactivado**: al publicar se activan todos los triggers y cada ejecución gasta 1 llamada a Gemini. Para usarlo: actívalo en el editor y vuelve a publicar. Con el schedule no se responde a ningún webhook (IF «¿Responder al webhook?»). GET /recomendaciones vive en el mismo workflow.
- Todo número sale del Code «Analizar y proponer» (céntimos enteros, formato es-ES propio: `1.234,56 €`, `14,2 %`, `dd/mm/aaaa`). Periodo: facturas `ok/revisar/posible_duplicada` con `fecha_emision` en [desde, hasta]; `referencia = min(hasta, hoy)`.
- Detectores (`hallazgos`):
  - `suscripciones_activas`: última factura del periodo con 0 ≤ días hasta la referencia ≤ intervalo + margen (intervalo semanal 7 … anual 366; margen = mitad del intervalo, entre 10 y 45 días). Sin periodicidad ⇒ `sin_periodicidad`.
  - `solapes`: suscripciones activas con la misma subcategoría normalizada o el mismo tipo de servicio por palabras clave en proveedor/subcategoría/conceptos (música, vídeo, nube, gimnasio, videojuegos). Se conserva la más cara; el ahorro es el coste de las demás (con dos, la más barata).
  - `subidas_precio`: solo recurrentes activos; último importe > anterior del mismo `proveedor_norm`; impacto = diferencia × periodos/año (mensual = anual/12).
  - `categorias_crecen`: último mes completo (≤ referencia y ≥ mes de `desde`) con gasto, frente a la media de los 3 meses anteriores calculada con todas las facturas válidas; umbral +25 % y +10 €; si la media es 0 no cuenta (sería una categoría nueva).
  - `gasto_hormiga`: ≥ 5 compras `puntual` < 15 € de la misma categoría en una ventana de 30 días (con el dataset: vacío).
  - `vencimientos`: `fecha_vencimiento` entre hoy y hoy + 15 días (cualquier fecha de emisión).
- Candidatos: uno por solape y por subida, uno agrupado de vencimientos, uno por hormiga y por categoría que crece, uno de suscripciones activas (coste mensual y anual). Orden: ahorro anual desc. y, a igualdad, solape > subida > vencimiento > hormiga > crece > suscripciones > info. Máximo 6; si hay < 3 se completa con `info` (categoría principal, comparación con el periodo anterior, proveedor principal) sin ahorros. Ahorro 0 en vencimiento, crece, hormiga, suscripciones e info (no se estima un ahorro que no se puede calcular).
- Gemini (HTTP + `googlePalmApi` + `responseSchema` `{recomendaciones:[{id (enum), titulo, texto}]}`, principal → respaldo si falla; sin reintentos para no gastar cuota) solo redacta. El Code «Controlar redacción» extrae las cifras del título y del texto (todas las lecturas posibles: `1.234,56`, `1234.56`, `14,2`) y exige que cada una esté en `dato`, `titulo_base` o los ahorros del candidato; si no, o si la redacción falta, está vacía o es demasiado larga, o si Gemini falla, usa la plantilla `dato + acción fija` con `redaccion = "plantilla"` (motivos en `redaccion.control`). El asesor nunca falla por el LLM. Las cifras escritas con letras no se controlan (el prompt lo prohíbe).
- Ortografía: el prompt exige español correcto con tildes (música, próximo, suscripción…) y copiar los nombres de proveedor tal cual del dato. Además «Controlar redacción» corrige de forma determinista una lista corta de palabras sin tilde en título y texto de Gemini (musica/s, proximo/a/s, suscripcion, electronica/o/s, energia/s → con tilde, conservando mayúsculas; respeta las palabras que aparecen tal cual en `dato` o `titulo_base`, p. ej. dentro de un nombre de proveedor). No toca cifras: el control de cifras es el mismo. Ejecución real 2026-10-15: 5/5 redactadas por `gemini-3.5-flash-lite` («Pagas dos veces por música en streaming»), 0 plantillas.
- Guarda `{fecha, desde, hasta, json}` en fact_recomendaciones (`json` = respuesta completa).
- Ejecución real 2026-10-14: 5 recomendaciones (solape de música 10,99 €/mes · 131,88 €/año; subida de Netflix 1,99 €/mes · 23,88 €/año; vencimiento de Iberdrola; crecimiento de Streaming y música; suscripciones activas 177,41 €/mes · 2.128,92 €/año), todas redactadas por `gemini-3.5-flash-lite` porque `gemini-3.5-flash` devolvió 429 (cuota diaria gratuita agotada) y entró el respaldo.

### FACT — Exportar Excel: decisiones
- GET /exportar → «Parámetros» (igual que el asesor; 400 en JSON) → Leer facturas → Leer última recomendación (`executeOnce`) → Code «Generar Excel» (ExcelJS) → «Responder Excel» (binario con `Content-Type` XLSX, `Content-Disposition`, `Access-Control-Expose-Headers: Content-Disposition` y `Cache-Control: no-store`). Respond to Webhook admite cabeceras propias, así que la web puede leer el nombre del archivo.
- Excluye `borrada` y `duplicada`. Hojas:
  - **Resumen**: título, periodo, KPIs (total `SUM`, nº `COUNT`, recurrente mensual/anual enlazado a Suscripciones, periodo anterior —valor fijo porque esas facturas no están en el libro—, diferencia y variación con fórmula); tabla por categoría con `SUMIFS`/`COUNTIFS` sobre Facturas, % con fórmula, total `SUM`, barras de datos, autofiltro.
  - **Facturas**: Tabla de Excel `TablaFacturas` con filtros y fila de totales `SUBTOTAL(109, …)` en Base, Cuota IVA y Total.
  - **Por mes**: categoría × todos los meses del periodo con `SUMIFS(…, ">="&mes, …, "<="&EOMONTH(mes,0))`, totales `SUM` por fila y columna, escala de 3 colores.
  - **Suscripciones y contratos**: bloque COMÚN; coste mensual `ROUND(importe*periodos/12,2)`, anual `importe*periodos`, totales `SUM`, barras de datos en coste anual.
  - **Recomendaciones**: última de fact_recomendaciones; total de ahorro con `SUM`.
- Textos legibles solo en las hojas (los datos guardan los códigos): Tipo «Puntual / Suscripción / Contrato», Estado «Correcta / Revisar / Posible duplicada» (y «Duplicada»/«Borrada», que no se exportan), periodicidad y método de pago con la primera letra en mayúscula. Ninguna fórmula filtra por tipo ni por estado (SUMIFS/COUNTIFS solo por categoría y fecha), así que no hubo que adaptar fórmulas.
- Anchos: `max(contenido + 2, 12, cabecera + 6, ceil(cabecera × 1,1) + 4)` (con +4 la flecha aún tapaba «Moneda» en Excel 2016) (el 10 % por la negrita y 4 caracteres para la flecha del filtro/Tabla, con la cabecera centrada); mínimos 10 (Facturas, Suscripciones), 12 (Resumen, Por mes; los meses `mmm yyyy` cuentan como «ene 2026» ⇒ 13); en Resumen no cuentan los títulos combinados de las filas 1–2; en Recomendaciones anchos fijos 42/70/70/16/16 o la cabecera + 4 si es mayor.
- Impresión (todas las hojas, `configurarImpresion`): A4 horizontal, `fitToPage` con 1 página de ancho y alto libre (`fitToWidth 1`, `fitToHeight 0`), márgenes estrechos (0,25/0,25/0,75/0,75, encabezado/pie 0,3), fila 1 repetida (Resumen: filas 1–2) y área de impresión = rango usado. ExcelJS antepone `$` a cada extremo del área, por eso se le pasa `A$1:Q$16` (queda `$A$1:$Q$16`). Comprobado en Excel 16 por COM: abre sin reparación, 0 errores, los nombres `Print_Area`/`Print_Titles` existen (ojo: `PageSetup.PrintArea` por COM sale vacío incluso en un libro creado por Excel; mira `Names`), 1 página por hoja en PDF.
- Estilo: cabecera teal `0F4C5C` con texto blanco en negrita, filas alternas, bordes finos, fila de totales destacada, paneles inmovilizados, autofiltro (la hoja Facturas usa el de la Tabla), anchos según el contenido, `#,##0.00 "€"`, fechas `dd/mm/yyyy`. Cada fórmula lleva como caché su resultado calculado en Code y el libro tiene `fullCalcOnLoad` para que Excel recalcule al abrir.
- **Limitación del task runner**: el Code corre en otro contexto (vm) y ExcelJS no reconoce sus `Date` ni sus arrays (`instanceof` falla): un `Date` se escribía como texto `"2026-03-01T00:00:00.000Z"` y `addRow([...])` dejaba la fila vacía. Por eso las fechas se escriben como número de serie de Excel (es como Excel guarda las fechas; Excel y openpyxl las leen como fecha) y las filas celda a celda. `addTable({rows})` sí funciona.

- **Hover y scroll de la lista (2026-10-16, sustituye al contrato anterior de «no tocar»)**: a petición del usuario (la página «se bugeaba» al hacer scroll con la rueda y costaba apuntar una factura). Causa raíz: (1) `html{scroll-behavior:smooth}` hacía que la compensación `window.scrollBy` al plegarse la fila anterior se **animara**, así que la fila señalada huía del puntero y volvía; (2) el filtro del «mousemove sintético» por igualdad de coordenadas (`xyRaton`) fallaba con cualquier temblor y con el orden de eventos de Chrome; (3) cerca del inicio de la página (`scrollY` < altura del detalle, ~240 px) la compensación es imposible (no se puede subir más allá de 0) y la fila abierta se escapaba de debajo del puntero. Mecánica nueva (código junto a `activar()` en `web/index.html`; ya no hay `mouseover`): **intención** (solo cuenta un `mousemove` real ≥ 4 px del último punto atendido; la fila se abre cuando el puntero lleva 130 ms quieto y se toma con `elementFromPoint` en ese instante, sin leer layout por evento); **bloqueo durante el scroll** (`scroll`/`wheel` pasivos: no se abre ni cierra nada mientras se desplaza; hasta 220 ms después hace falta un movimiento de ≥ 12 px, y se atiende cuando el scroll lleva 60 ms parado); **compensación `behavior:'instant'`** en la misma tarea (`sinMover`) y `.list{overflow-anchor:none}` para que el navegador no compense también; **fila que «sobra»** (`.row.sobra`: si la fila abierta anterior queda encima y no se puede compensar, se deja desplegada sin vista previa y se pliega cuando hay margen, al terminar un scroll o en la siguiente activación; así solo hay una `.row.open`); **fila fijada** (`S.fijada`, clase `.row.fijada`, aviso «Fijada · clic o Esc para soltar» en la vista previa): clic o Enter fijan, el hover no la cambia; otro clic en otra fila fija esa, clic en la fijada, Esc, o moverse con el teclado (foco), la sueltan. Táctil/móvil sin cambios (el toque abre/pliega, nunca fija).
